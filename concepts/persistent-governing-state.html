Persistent governing state is a capability within the MO§ES governance framework. It gives the system a persistent internal reference against which intended actions can be evaluated. The governing state is presented to the system, not enforced by a separate checkpoint in the action path.

Capability

Give the system a persistent internal reference against which intended actions can be evaluated.

The system carries a reference — its principles, its lineage, and its current commitments — through its own operations. Before an action is taken, the system can evaluate the proposed action against that reference and decide whether to continue, abstain, or re-ground.

Architecture Flow

governing state
(principles, lineage, current commitments)
    ↓
system reasoning
    ↓
proposed action
    ↓
continuity evaluation
    ↓
continue / abstain / re-ground

The flow is internal to the system's reasoning. The governing state informs reasoning; reasoning produces a proposed action; the proposed action is evaluated for continuity against the governing state; and the system proceeds, abstains, or re-grounds. No external gate sits between "proposed action" and "continue."

The Architectural Claim

The governing state is presented to the system rather than enforced by a separate checkpoint in the action path.

This is the specific design distinction. The system evaluates its own proposed actions against the governing state, rather than an external gate blocking actions. The evaluation is part of the system's reasoning, not a separate interceptor that fires after reasoning is complete.

What "Presented, Not Enforced" Means

Traditional guardrails sit in the action path — they intercept and block. A guardrail is a checkpoint between the system's output and the world: the system proposes an action, the guardrail inspects it, and the guardrail blocks or allows it. The system itself does not evaluate; the gate does.

Persistent governing state is part of the system's reasoning context — it informs the system's own evaluation of whether to proceed. The system can choose to abstain or re-ground rather than being blocked. The difference is where the evaluation lives: in an external gate, or in the system's reasoning against a presented reference.

Components of Governing State

The governing state is composed of three parts:

  • Principles: what the system should preserve — the commitments and constraints that define legitimate action.
  • Lineage: the chain of authority and prior state — where the system's current state came from, and what authorizes it.
  • Current commitments: what the system is currently obligated to maintain — the obligations in force at this moment of operation.

Together these form the reference against which a proposed action is evaluated for continuity. An action that breaks the lineage, violates a principle, or drops a current commitment fails the continuity evaluation.

Relationship to Governance vs Alignment

Persistent governing state is the mechanism by which governance — not alignment — operates at execution time. Alignment shapes behavior at training time; governance preserves continuity at execution time. The governing state is what the system evaluates against to preserve that continuity through its own operations. See Governance vs Alignment.

Avoid Metaphysics

Call it Persistent Governing State — not "internal compass," not "conscience," not any anthropomorphic term. It is a data structure plus an evaluation protocol, not a personality. The system does not "feel" its governing state; it evaluates proposed actions against it. Keeping the language structural rather than anthropomorphic is what keeps the claim honest and the capability measurable.
